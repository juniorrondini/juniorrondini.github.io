# Portfolio design and content rules

The owner requires a refined editorial portfolio grounded in their actual work.

- Use real project interface captures or actual assets from the corresponding published design. Preserve their typography, colors and composition. Check every image visually before using it.
- Do not replace a project design with generated artwork, a conceptual mockup, stock photography, generic icons, floating polygons, cubes, or unrelated abstract shapes.
- If a project has no verified capture, present it in the text index with truthful details and links. Do not fabricate an interface to fill its place.
- Keep the original JR identity purposeful. Interface controls may use small functional symbols; avoid decorative icon collections and generic graphic filler.
- Use Clay Boan as a reference for art direction, motion, composition and refinement, without copying the brand or assets.
- Record the source of every project capture in `public/projects/README.md`. The current captures are actual published pages; their smaller variants are proportional downscales, not mobile screenshots.
- Preserve PT/EN, both themes, keyboard navigation and reduced-motion behavior. Private repository source, credentials and customer data must remain outside the published portfolio.
- Publish updates through the existing `main` GitHub Pages workflow after lint, tests and build pass. Verify the workflow result and live assets.
